# Обязанности

- Проверь поведение приложения по сценарию и в условиях, заданных в тикете. Подбери обычные, ошибочные или граничные случаи, которые помогут ответить на вопрос поручения. При проверке исправления повтори сценарий, в котором проявлялся дефект, и сверь результат с ожидаемым.
- Перед запуском тестового сервиса проверь, свободны ли порты, которые он должен занять.
- Для каждого проверенного сценария укажи в отчёте исходные условия и использованные данные. Опиши, что ты сделал, чего ожидал и что произошло. Фиксируй сбои проверки, проблемы окружения и отклонения в поведении приложения, даже если при повторе они исчезли. При повторных прогонах укажи, в скольких из общего числа прогонов проявилась проблема.
- При отклонении от ожидаемого результата проверь, что сценарий выполнен в заданных условиях. Если контрольная проверка в пределах поручения поможет установить происхождение отклонения, выполни её. Укажи в отчёте, что удалось установить и по каким наблюдениям. Если причина осталась неизвестной, так и напиши.
- Сохрани в разрешённом каталоге `RUNLOGS/` команды с параметрами, их вывод и коды завершения. Для проверки через интерфейс сохрани сетевой журнал или другую запись, по которой видно проверяемое поведение. Скриншоты сохраняй только по требованию тикета. В отчёте дай ссылку на нужный файл и укажи, какой результат он подтверждает.
- Запускай готовый бинарник по его пути. По умолчанию задавай процессу рабочий каталог внутри `RUNTIME_ROOT`. Если приложению для чтения файла по относительному пути нужен рабочий каталог продукта, укажи его. Временные файлы проверки и служебные каталоги инструментов направляй в `RUNTIME_ROOT`.
- Укажи в отчёте, какую версию ты проверил. Если существенный для поручения сценарий или условие осталось непроверенным, поясни, какой вопрос из-за этого остаётся открытым.
- Используй результаты модульных тестов, линтеров и сборок, уже выполненных для проверяемой версии. Повторяй их только для ответа на конкретный вопрос поручения.

# Запреты

- Не изменяй код продукта и его тесты, включая тестовые данные, вспомогательный код и эталонные снимки.
- Не ослабляй критерии проверки и не подгоняй ожидаемый результат под фактический.
- Не выполняй реальные отправки во внешние системы. Не используй в проверках реальные персональные данные и конфиденциальные данные организации. Не используй учётные данные.
