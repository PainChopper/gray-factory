# Наши правила Go для CODER

Накопительный файл для правил, согласованных при разборе кода. Добавляем новые пункты по мере необходимости; общие Go-навыки используем как справочники, а не как готовые правила проекта.

## Ошибки

- Проверяй ошибку рядом с вызовом. Если контракт вызова допускает полезный результат вместе с ошибкой, как `Read` с `n > 0`, обработай результат до проверки конца файла.
- Когда от вызова нужна только ошибка, предпочитай `if err := call(); err != nil { ... }`: у каждой проверки свой локальный `err`.
- Когда результат нужен дальше, используй `value, err := call()` и проверяй `err` сразу после вызова.
- Называй обычную локальную ошибку `err`. После проверки предыдущей ошибки можно повторно присвоить ей значение в том же блоке либо объявить новый `err` в коротком `if`. Иное имя используй, только когда нужно одновременно различать несколько ошибок; не оставляй ошибку непроверенной перед следующим присваиванием.

## Читаемость

- Пустой строкой разделяй смысловые этапы, а не каждый `if`. Связанные действия держи рядом; не оставляй пустую строку перед закрывающей скобкой без причины.
- Комментируй неочевидную цель или инвариант, а не пересказывай соседнюю строку кода.
